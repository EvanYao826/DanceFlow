# 阶段 6：管理端与数据统计

## 1. 阶段目标

整合各业务模块的管理能力，完成后台 CRUD、状态操作、审核工作台、数据概览和操作日志，形成可用于演示和日常维护的管理端。

## 2. 后端管理接口

### 2.1 用户与系统

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/users` | 用户分页、关键词、状态筛选 |
| PUT | `/api/admin/users/{id}/status` | 启用或禁用用户 |
| PUT | `/api/admin/users/{id}/roles` | 分配角色 |
| PUT | `/api/admin/users/{id}/reset-password` | 重置密码 |
| GET | `/api/admin/logs` | 查询操作日志 |
| GET | `/api/admin/dicts/{type}` | 查询舞种、难度等字典 |
| PUT | `/api/admin/dicts/{id}` | 修改字典项 |

### 2.2 统计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/statistics/overview` | 总用户、成员、活动、课程、作品等 |
| GET | `/api/admin/statistics/user-trend` | 指定日期范围的用户增长 |
| GET | `/api/admin/statistics/activity` | 活动发布、报名和完成统计 |
| GET | `/api/admin/statistics/content` | 作品、帖子、评论和互动统计 |
| GET | `/api/admin/statistics/ranking` | 热门作品、活跃用户或舞种排行 |

统计接口接收 `startDate`、`endDate` 和粒度参数，返回前端直接绘图所需的数组。日期范围、时区和空数据返回格式必须固定。

## 3. 后端实现要求

1. 对已有模块补齐管理端查询条件、分页、状态操作和逻辑删除。
2. 所有管理员写操作记录操作者、目标资源、动作、请求路径和结果。
3. 统计 SQL 仅查询必要字段，时间字段建立索引；热点概览可以使用 Redis 短时缓存。
4. 超级管理员才可以修改角色权限、系统字典和其他超级管理员账号。
5. 防止管理员通过请求参数修改不可编辑字段，例如创建人、计数和审核记录。

## 4. 前端实现

### 4.1 管理页面

- `/admin/dashboard`：指标卡、用户趋势、活动趋势、内容分布和排行。
- `/admin/users`：用户表格、状态操作、角色分配和重置密码。
- `/admin/members`：成员审核和档案维护。
- `/admin/activities`、`/admin/courses`、`/admin/works`：分别对应业务管理。
- `/admin/notices`、`/admin/posts`、`/admin/comments`：社区内容维护。
- `/admin/logs`、`/admin/settings`：日志和基础配置。

### 4.2 交互要求

- 表格统一支持分页、刷新、筛选条件重置和操作确认。
- 删除、下架、禁用、驳回等不可逆或影响展示的动作必须二次确认。
- 数据大屏提供日期范围选择、刷新按钮和图表空状态。
- 权限不足的按钮不展示，直接访问地址仍由后端拦截。

## 5. 测试与验收

- 三类角色看到的菜单、按钮和接口权限符合设计。
- 统计数字可由数据库查询复核，时间范围边界正确。
- 管理操作日志能够定位操作者、时间、动作和目标。
- 大量数据分页不会导致页面卡顿或一次性加载全部记录。
- 禁用用户不能继续调用需要登录的业务接口。

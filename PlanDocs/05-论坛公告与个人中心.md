# 阶段 5：论坛公告与个人中心

## 1. 阶段目标

补齐社团交流和用户聚合页面，把活动、课程、作品等模块产生的数据汇总到个人中心，形成可展示的社员成长记录。

## 2. 数据库设计

`forum_post`：`id`、`user_id`、`title`、`content`、`cover_url`、`category`、`status`、`view_count`、`like_count`、通用字段。

`notice`：`id`、`title`、`content`、`publisher_id`、`publish_status`、`publish_time`、`top_flag`、通用字段。

`user_point_log`：`id`、`user_id`、`point_type`、`point_value`、`source_type`、`source_id`、`remark`、通用字段。建议按来源和来源 ID 防止重复发放积分。

## 3. 后端接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/community/posts` | 公开/登录 | 查询帖子列表 |
| GET | `/api/community/posts/{id}` | 公开/登录 | 帖子详情并增加浏览量 |
| POST | `/api/community/posts` | 登录 | 发布帖子 |
| PUT | `/api/community/posts/{id}` | 作者/管理员 | 编辑帖子 |
| DELETE | `/api/community/posts/{id}` | 作者/管理员 | 删除帖子 |
| GET | `/api/notices` | 公开 | 查询已发布公告 |
| GET | `/api/notices/{id}` | 公开 | 公告详情 |
| POST | `/api/admin/notices` | 管理员 | 创建公告 |
| PUT | `/api/admin/notices/{id}` | 管理员 | 编辑公告 |
| PUT | `/api/admin/notices/{id}/status` | 管理员 | 发布或下线公告 |
| GET | `/api/users/me/overview` | 登录 | 个人统计和成长信息 |
| GET | `/api/users/me/works` | 登录 | 我的作品 |
| GET | `/api/users/me/activities` | 登录 | 我的活动 |
| GET | `/api/users/me/courses` | 登录 | 我的学习 |
| GET | `/api/users/me/collections` | 登录 | 我的收藏 |
| GET | `/api/users/me/points` | 登录 | 积分流水 |

个人概览返回作品数、活动数、课程完成数、获赞数、收藏数、总积分和等级。等级规则必须配置为常量或系统配置，避免散落在前端。

## 4. 前端实现

- `/community`：帖子列表、分类筛选、置顶公告区域。
- `/community/posts/:id`：正文、作者、浏览量、评论和相关推荐预留。
- `/community/posts/create`：帖子编辑器、分类和封面。
- `/profile`：资料卡、统计数字、成长等级、最近动态。
- `/profile/works`、`/profile/activities`、`/profile/courses`、`/profile/collections`：个人数据分页页。
- `/admin/notices` 和 `/admin/posts`：公告、帖子审核及下线管理。

## 5. 业务规则

- 普通用户可编辑和删除自己的帖子，管理员可隐藏违规帖子。
- 未发布公告不可在用户端展示，置顶公告按置顶标志和发布时间排序。
- 发布作品、完成课程、参加活动、获得点赞可按规则写入积分；重复触发不重复累计。
- 个人中心所有列表均使用分页，不能一次请求全部历史数据。

## 6. 测试与验收

- 个人中心统计与对应业务表数据一致。
- 用户无法访问或修改他人的私有列表。
- 帖子、公告的发布状态在前后台显示一致。
- 积分来源可追溯，重复回调不会重复发放。

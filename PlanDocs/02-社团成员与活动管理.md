# 阶段 2：社团成员与活动管理

## 1. 阶段目标

实现社团最核心的组织管理能力：入社申请、成员档案、活动发布、活动报名和报名统计。

## 2. 数据库设计

`club_member`：`id`、`user_id`、`dance_type`、`skill_level`、`join_date`、`member_status`、`bio`、通用字段。`member_status`：`PENDING`、`ACTIVE`、`REJECTED`、`QUIT`。

`activity`：`id`、`title`、`cover_url`、`description`、`activity_type`、`start_time`、`end_time`、`location`、`capacity`、`apply_deadline`、`status`、`publisher_id`、通用字段。状态：`DRAFT`、`PUBLISHED`、`CLOSED`、`FINISHED`、`CANCELLED`。

`activity_apply`：`id`、`activity_id`、`user_id`、`apply_status`、`remark`、`apply_time`、通用字段。活动和用户建立联合唯一约束。

## 3. 后端接口

### 3.1 成员

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/members/apply` | 登录 | 提交入社申请 |
| GET | `/api/members/me` | 登录 | 查看本人社员档案 |
| GET | `/api/members` | 管理员 | 分页查询成员 |
| GET | `/api/members/{id}` | 登录 | 查看成员详情 |
| PUT | `/api/members/{id}` | 管理员/本人 | 修改档案 |
| PUT | `/api/members/{id}/audit` | 管理员 | 审核入社申请 |
| PUT | `/api/members/{id}/status` | 管理员 | 设置成员状态 |

审核参数：`status`、`reason`。必须校验只有 `PENDING` 才能审核，审核通过时写入 `join_date`。

### 3.2 活动

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/activities` | 公开/登录 | 分页查询已发布活动 |
| GET | `/api/activities/{id}` | 公开/登录 | 活动详情和报名状态 |
| POST | `/api/activities/{id}/apply` | 登录 | 报名活动 |
| DELETE | `/api/activities/{id}/apply` | 登录 | 取消报名 |
| GET | `/api/activities/my` | 登录 | 我的报名列表 |
| POST | `/api/admin/activities` | 管理员 | 创建活动 |
| PUT | `/api/admin/activities/{id}` | 管理员 | 编辑活动 |
| PUT | `/api/admin/activities/{id}/status` | 管理员 | 发布、关闭或取消 |
| GET | `/api/admin/activities/{id}/applications` | 管理员 | 报名名单和统计 |
| DELETE | `/api/admin/activities/{id}` | 管理员 | 逻辑删除草稿或已下架活动 |

报名时必须在事务内校验活动状态、截止时间、人数上限和重复报名；人数统计以报名记录为准，避免并发超卖。

## 4. 前端实现

### 4.1 用户端

- `/club`：社团介绍、成员风采和入社申请。
- `/activities`：活动卡片、舞种/类型/状态筛选、分页。
- `/activities/:id`：详情、时间地点、剩余名额、报名/取消报名按钮。
- `/profile/applications`：我的报名记录。

### 4.2 管理端

- `/admin/members`：成员表格、筛选、详情抽屉、审核弹窗。
- `/admin/activities`：活动表格、搜索、状态筛选、新增/编辑表单。
- `/admin/activities/:id/applications`：报名名单、人数统计和导出预留。

表单必须校验开始时间早于结束时间，报名截止时间早于开始时间，容量为正整数；活动详情要展示报名状态和失败原因。

## 5. 测试与验收

- 同一用户不能重复报名；满员后不能继续报名。
- 截止时间后不能报名；取消报名后名额恢复。
- 管理员发布的活动能在用户端列表出现，草稿不会公开。
- 入社申请只能被审核一次，普通用户不能修改他人档案。
- 活动删除后详情不可访问，但数据库记录可追溯。

# 阶段 1：基础设施与认证权限

## 1. 阶段目标

建立前后端可运行骨架、统一开发规范、用户认证、角色权限和基础布局，为所有业务模块提供登录态和权限基础。

## 2. 数据库

### 2.1 表设计

`sys_user`：`id`、`username`、`password`、`nickname`、`avatar`、`phone`、`email`、`role`、`status`、`last_login_time`、通用字段。`username` 唯一，`status`：`0` 禁用、`1` 正常。

`sys_role`：`id`、`role_code`、`role_name`、`status`、通用字段。角色基线：`USER`、`ADMIN`、`SUPER_ADMIN`。

`sys_permission`：`id`、`permission_code`、`permission_name`、`type`、`parent_id`、`path`、`status`。

`sys_user_role`：`user_id`、`role_id`，建立联合唯一约束。

`sys_role_permission`：`role_id`、`permission_id`，建立联合唯一约束。

初始化三个角色和最小菜单权限。密码使用 BCrypt，不保存明文或可逆加密密码。

## 3. 后端实现顺序

1. 创建 Spring Boot 工程，配置 MySQL、Redis、MyBatis-Plus、参数校验和 Swagger。
2. 编写统一响应 `Result<T>`、分页对象、错误码枚举和全局异常处理器。
3. 实现 JWT 工具、登录用户上下文、认证过滤器和 Security 配置。
4. 实现用户注册、登录、当前用户信息、修改资料和修改密码。
5. 实现角色/权限读取，保护管理端接口。
6. 增加请求日志和登录日志，禁止日志输出密码与完整 Token。

## 4. 后端接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | 公开 | 注册账号 |
| POST | `/api/auth/login` | 公开 | 登录并返回 Token |
| POST | `/api/auth/logout` | 登录 | 注销当前登录态 |
| GET | `/api/auth/me` | 登录 | 获取当前用户和权限 |
| PUT | `/api/users/me` | 登录 | 修改昵称、头像、手机等 |
| PUT | `/api/users/me/password` | 登录 | 修改密码 |
| GET | `/api/users/{id}` | 登录 | 查看公开用户资料 |
| GET | `/api/admin/roles` | 管理员 | 获取角色列表 |
| GET | `/api/admin/permissions` | 管理员 | 获取权限树 |

注册参数：`username` 3-30 位、`password` 8-32 位、`nickname` 2-30 位。登录返回 `token`、`expiresIn`、`user` 和 `permissions`。密码修改要求旧密码、新密码和确认密码一致。

## 5. 前端实现

### 5.1 路由与页面

- `/login` 登录页。
- `/register` 注册页。
- `/` 用户端基础布局和首页占位。
- `/admin` 管理端基础布局和首页占位。
- `/403` 无权限页、`/404` 页面不存在页。

### 5.2 组件与状态

- `stores/auth.ts`：Token、用户信息、权限、登录、退出和恢复登录。
- Axios 请求/响应拦截器、路由守卫和动态管理菜单。
- 登录注册表单、头像上传占位、顶部用户菜单、侧边栏菜单、面包屑和全局 loading。

## 6. 测试与验收

- 正确账号可以登录，错误密码、禁用账号和不存在账号有明确提示。
- 未登录访问业务接口返回 401，普通用户访问管理接口返回 403。
- 刷新页面后登录态可恢复，退出后 Token 不再可用。
- 注册用户名重复、密码不符合规则和两次密码不一致会被拦截。
- 前后台布局在桌面和移动宽度下不发生主要内容重叠。

# DanceFlow 开发阶段总览与执行规范

## 1. 使用方式

本目录将 DanceFlow 拆分为可独立开发、联调和验收的阶段。每个阶段均遵循以下顺序：

1. 数据库表和初始化数据。
2. 后端 Entity、Mapper、Service、Controller、参数校验和权限。
3. 使用 Swagger/OpenAPI 或接口测试工具验证后端接口。
4. 前端 API 封装、类型定义、页面和交互状态。
5. 前后端联调、异常处理、测试和阶段验收。

后续每次开发应以一个阶段文档为任务边界，完成后再进入下一个阶段。阶段文档中的字段和接口是推荐基线，可在实际编码时小幅调整，但调整必须同步更新接口文档和数据库脚本。

## 3. 统一技术约定

### 3.1 后端

- Java 17、Spring Boot 3、MyBatis-Plus、MySQL 8、Redis、Spring Security、JWT。
- 包结构：`controller`、`service`、`service.impl`、`mapper`、`entity`、`dto`、`vo`、`config`、`exception`、`common`。
- Controller 只负责参数接收和调用 Service；业务规则放在 Service；Mapper 不承载业务判断。
- 所有写操作使用 DTO，查询返回 VO，禁止直接暴露 Entity。
- 统一返回：`{ code, message, data, timestamp }`；成功码为 `200`，参数错误 `400`，未登录 `401`，无权限 `403`，资源不存在 `404`，服务器错误 `500`。

### 3.2 通用字段

业务表默认包含：`id BIGINT`、`create_time DATETIME`、`update_time DATETIME`、`create_by BIGINT`、`update_by BIGINT`、`is_deleted TINYINT`。时间统一使用服务器时区，前端按 `YYYY-MM-DD HH:mm:ss` 展示。

### 3.3 分页和列表

请求参数统一使用 `page`（从 1 开始）、`pageSize`（默认 10，最大 100）、`keyword`、`status`、`sortBy`、`sortDirection`。返回 `records`、`total`、`page`、`pageSize`。

### 3.4 前端约定

- Vue 3 + TypeScript + Vite + Pinia + Vue Router + Element Plus + Axios。
- `src/api` 只封装请求；`src/stores` 保存登录态和跨页面状态；`src/views` 组合页面；通用表格、上传和空状态放在 `src/components`。
- 请求拦截器自动带 `Authorization: Bearer <token>`；响应拦截器统一处理 401、403 和业务错误。
- 每个页面必须实现 loading、空数据、请求失败、表单校验、提交中和成功/失败提示。

## 4. 每个功能的完成定义

- 数据库脚本可重复执行或明确初始化顺序。
- 后端接口具备参数校验、业务异常、权限校验和基本日志。
- 接口可通过 Swagger 或 Postman 按文档调用。
- 前端已接入真实接口，不使用最终展示用硬编码数据。
- 成功、失败、空列表、无权限和未登录场景均可操作。
- 至少覆盖核心成功路径和两个边界场景。
- 阶段文档中的验收条件全部满足后，才标记阶段完成。

## 5. 推荐开发分支与提交

建议按阶段创建分支：`feature/stage-01-auth`、`feature/stage-02-activity` 等。提交信息使用 `feat`、`fix`、`refactor`、`test`、`docs` 前缀。数据库变更、接口变更和页面变更应在同一阶段提交中保持可追踪。

# 阶段 4：作品社区与互动

## 1. 阶段目标

实现平台的主要展示亮点：作品上传、审核、瀑布流展示、详情、点赞、收藏和评论。首期文件可以使用本地存储，接口设计保留切换对象存储的空间。

## 2. 数据库设计

`dance_work`：`id`、`user_id`、`title`、`cover_url`、`media_url`、`media_type`、`description`、`dance_type`、`audit_status`、`audit_reason`、`like_count`、`comment_count`、`collection_count`、`view_count`、`published_time`、通用字段。状态：`PENDING`、`PUBLISHED`、`REJECTED`、`OFFLINE`。

`work_like`：`work_id`、`user_id`、通用字段，联合唯一。

`work_collection`：`work_id`、`user_id`、通用字段，联合唯一。

`work_comment`：`id`、`work_id`、`user_id`、`parent_id`、`content`、`status`、通用字段。首期支持两级评论，状态为正常或隐藏。

## 3. 文件服务

实现 `FileStorageService` 接口，首期提供 `LocalFileStorageService`。文件名使用 UUID，按日期分目录保存；限制视频、图片类型和大小；数据库只保存 URL、原始名称、大小、类型和存储键。后续可替换为 OSS 实现。

## 4. 后端接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/files/upload` | 登录 | 上传图片、视频或封面 |
| GET | `/api/works` | 公开/登录 | 分页查询已发布作品 |
| GET | `/api/works/{id}` | 公开/登录 | 作品详情并增加浏览量 |
| POST | `/api/works` | 登录 | 创建待审核作品 |
| PUT | `/api/works/{id}` | 作者/管理员 | 编辑作品 |
| DELETE | `/api/works/{id}` | 作者/管理员 | 删除或下架作品 |
| POST | `/api/works/{id}/like` | 登录 | 点赞或取消点赞 |
| POST | `/api/works/{id}/collection` | 登录 | 收藏或取消收藏 |
| GET | `/api/works/{id}/comments` | 公开/登录 | 查询评论 |
| POST | `/api/works/{id}/comments` | 登录 | 发表评论 |
| DELETE | `/api/comments/{id}` | 作者/管理员 | 删除或隐藏评论 |
| GET | `/api/admin/works` | 管理员 | 查询待审核作品 |
| PUT | `/api/admin/works/{id}/audit` | 管理员 | 通过或驳回作品 |

点赞和收藏接口应幂等，返回 `liked`、`collected` 和最新计数。发布作品默认进入待审核，不得直接公开。评论内容需要长度校验和基础敏感词拦截。

## 5. 前端实现

- `/works`：瀑布流或响应式网格、舞种筛选、排序、分页/加载更多。
- `/works/create`：封面、媒体文件、标题、舞种和描述表单。
- `/works/:id`：视频/图片展示、作者信息、计数、点赞、收藏和评论。
- `/profile/works`：我的作品和审核状态。
- `/admin/works`：审核列表、预览、通过/驳回弹窗。

上传组件必须展示进度、类型错误、大小错误、网络失败和重试入口。移动端作品详情应避免视频与评论区域互相遮挡。

## 6. 测试与验收

- 非法文件类型和超大文件不能上传。
- 作品审核通过后才出现在公开列表；驳回原因可被作者查看。
- 同一用户重复点击点赞或收藏不会造成计数错误。
- 作者只能编辑或删除自己的作品，管理员可以处理全部作品。
- 删除作品后关联评论、点赞和收藏的处理策略已实现并有测试。

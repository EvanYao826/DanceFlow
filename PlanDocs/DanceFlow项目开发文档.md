# DanceFlow 项目开发文档

## 1. 文档说明

### 1.1 项目名称

- 中文名称：基于 SpringBoot + Vue 的高校街舞社团综合服务平台
- 英文名称：DanceFlow
- 文档用途：用于项目立项、系统设计、开发任务拆分、测试验收及毕业论文编写

### 1.2 项目定位

DanceFlow 面向高校街舞社团，提供社员管理、活动组织、舞蹈课程、作品展示、社区交流和数据统计等功能。系统采用前后端分离架构，分为用户端和管理端，目标是将社团日常管理和成员交流统一到一个平台中。

### 1.3 建设目标

1. 统一维护社团成员、活动、课程和作品等业务数据。
2. 支持活动在线发布、报名、审核和统计。
3. 提供舞蹈作品展示及点赞、收藏、评论等互动能力。
4. 为社员建立个人主页和成长记录，沉淀社团活动数据。
5. 通过可视化数据大屏辅助管理员了解平台运行情况。
6. 保证系统结构清晰，便于后续扩展 AI 舞蹈点评和智能推荐能力。

## 2. 用户角色与权限

### 2.1 普通用户/社员

- 注册、登录和维护个人资料。
- 浏览社团动态、活动、课程和舞蹈作品。
- 申请加入社团、报名或取消活动。
- 学习课程并记录学习进度。
- 发布作品、发表评论、点赞和收藏。
- 查看个人作品、活动记录、获赞数据和成长等级。

### 2.2 舞者/社团管理员

- 管理社员档案和入社申请。
- 发布、编辑和维护活动信息。
- 创建和维护课程、课时及教学资料。
- 审核用户上传的作品和社区内容。
- 发布公告，管理评论和违规内容。
- 查看成员、活动、作品等统计数据。

### 2.3 超级管理员

- 管理系统用户、角色和权限。
- 配置系统基础参数。
- 维护字典、分类、敏感词等基础数据。
- 执行数据维护、日志查看和异常处理。

## 3. 系统范围

### 3.1 用户端

1. 首页：展示社团介绍、宣传视频、最新活动、热门作品和优秀舞者。
2. 用户认证：注册、登录、退出、Token 管理和个人资料维护。
3. 社团中心：查看社团信息、成员风采和加入社团。
4. 活动中心：活动列表、活动详情、报名、取消报名和报名记录。
5. 课程中心：按舞种或难度浏览课程，查看课程详情和学习进度。
6. 作品社区：瀑布流展示作品，支持发布、详情查看、点赞、收藏和评论。
7. 动态论坛：发布社团动态或讨论帖子，支持评论和互动。
8. 个人中心：展示个人资料、作品、活动、收藏、点赞和成长数据。

### 3.2 管理端

1. 数据概览：展示用户、成员、活动、课程、作品和访问量等指标。
2. 用户管理：查询用户、修改状态、分配角色和重置账号信息。
3. 成员管理：审核入社申请，维护舞种、等级、入社时间等档案信息。
4. 活动管理：活动新增、编辑、发布、下架、删除和报名统计。
5. 课程管理：课程分类、课程信息、课时资料和上下架管理。
6. 作品审核：审核视频或图片作品，处理违规内容。
7. 社区管理：公告、帖子、评论、点赞和收藏相关数据管理。
8. 系统设置：角色权限、舞种分类、难度等级、文件配置和操作日志。

### 3.3 暂不纳入首期范围

- 实时音视频直播。
- 复杂的商业支付和会员订阅。
- 专业级动作识别和医疗级运动分析。
- 多社团租户隔离。

## 4. 核心业务流程

### 4.1 用户认证流程

用户注册账号后登录，后端校验账号密码并签发 JWT。前端保存 Token，在后续请求中携带认证信息；Token 失效后引导用户重新登录。

### 4.2 入社流程

用户浏览社团信息并提交入社申请，管理员审核申请。审核通过后生成或更新成员档案，用户获得社员身份及对应功能权限。

### 4.3 活动报名流程

管理员发布活动并设置时间、地点、人数上限和报名截止时间。用户提交报名，系统校验重复报名、报名状态和人数限制；管理员可查看报名名单和统计结果。

### 4.4 作品发布流程

用户上传作品文件和描述信息，作品进入待审核状态。管理员审核通过后公开展示，用户可对已发布作品进行点赞、收藏和评论。

### 4.5 课程学习流程

管理员创建课程和课时资料，用户进入课程后学习并记录完成状态。个人中心展示已学课程和学习进度。

## 6. 功能模块概要

### 6.1 用户与权限模块

负责注册、登录、退出、个人信息、角色权限和接口访问控制。密码必须加密存储，管理端接口需要进行角色或权限校验。

### 6.2 社团成员模块

维护成员基本资料、舞种、技能等级、入社时间和成员状态。支持关键字查询、条件筛选、详情查看和管理员维护。

### 6.3 活动模块

支持比赛、训练、演出、团建等活动类型。重点处理活动状态、报名人数、报名截止时间、重复报名和取消报名等规则。

### 6.4 课程模块

按舞种、难度和课程状态管理教学内容。课程可包含多个课时，每个课时可关联视频、封面、文字说明和学习顺序。

### 6.5 作品社区模块

提供作品发布、审核、展示和互动。首期支持视频或图片作品，建议采用“待审核、已发布、已驳回、已下架”等状态控制内容生命周期。

### 6.6 论坛与公告模块

用于社团通知、排练安排、经验交流和问题讨论。公告由管理员发布，帖子和评论由用户产生并接受审核或违规处理。

### 6.7 个人成长模块

聚合用户的作品、活动、课程学习、点赞和收藏数据。可基于规则计算积分和等级，首期建议使用简单可解释的积分规则。

### 6.8 统计分析模块

通过 ECharts 展示成员增长、活动数量、报名情况、作品数量、互动数据和访问趋势。统计接口应只返回前端展示所需的数据。

## 7. 数据库设计概要

### 7.1 核心表

| 表名 | 用途 |
| --- | --- |
| `sys_user` | 用户账号、密码、头像、联系方式和状态 |
| `sys_role` | 角色信息 |
| `sys_permission` | 菜单和接口权限 |
| `sys_user_role` | 用户与角色关联 |
| `club_member` | 社员档案和社团身份 |
| `activity` | 活动基础信息 |
| `activity_apply` | 活动报名记录 |
| `course` | 课程基础信息 |
| `course_lesson` | 课程课时信息 |
| `learning_record` | 用户学习进度 |
| `dance_work` | 舞蹈作品信息和审核状态 |
| `work_comment` | 作品或帖子评论 |
| `work_like` | 作品点赞记录 |
| `work_collection` | 作品收藏记录 |
| `forum_post` | 社区帖子 |
| `notice` | 社团公告 |
| `operation_log` | 管理员操作日志 |

### 7.2 通用字段建议

业务表建议统一包含 `id`、`create_time`、`update_time`、`create_by`、`is_deleted` 等字段。涉及状态流转的表应增加明确的状态字段和必要的审核信息。

### 7.3 数据设计原则

- 用户账号、点赞、收藏和报名关系应建立唯一约束，避免重复数据。
- 常用查询字段建立索引，例如用户状态、活动状态、作品审核状态和创建时间。
- 文件数据库字段只保存文件地址、类型、大小和封面等元数据。
- 删除优先采用逻辑删除，保留可追溯数据。

## 8. 接口设计约定

### 8.1 基本规范

- API 前缀建议为 `/api`。
- 使用 REST 风格命名资源。
- 统一返回结构：`code`、`message`、`data`、`timestamp`。
- 分页参数统一为 `page`、`pageSize`，返回总数和数据列表。
- 统一处理参数校验、业务异常、权限异常和系统异常。

### 8.2 接口分组示例

```text
/api/auth/*          认证相关
/api/users/*         用户相关
/api/members/*       成员相关
/api/activities/*    活动相关
/api/courses/*       课程相关
/api/works/*         作品相关
/api/community/*     帖子、评论、公告
/api/statistics/*    统计相关
/api/admin/*         管理端操作
```

### 8.3 文件上传约定

限制文件类型和大小，上传后返回文件地址及元信息。服务端应校验文件扩展名、MIME 类型和用户权限；生产环境建议使用对象存储，并避免直接暴露本地存储路径。

## 9. 非功能需求

- 安全性：密码加密、JWT 校验、权限控制、参数校验和上传安全检查。
- 可用性：常见操作有明确的成功、失败、加载和空数据提示。
- 性能：列表接口支持分页，首页和统计数据可使用缓存，避免一次性加载大量视频。
- 可维护性：按业务模块分层，统一异常、日志、响应和枚举定义。
- 兼容性：适配主流桌面浏览器，并对移动端页面进行基础响应式适配。
- 可扩展性：为 AI 点评、推荐算法和多社团管理预留模块边界。

## 11. 开发阶段与任务拆分

### 阶段一：项目基础建设

- 初始化前后端项目和开发环境。
- 建立数据库、代码规范和统一响应结构。
- 完成登录注册、JWT、权限模型和基础布局。

### 阶段二：核心管理业务

- 完成用户和成员管理。
- 完成活动发布、报名和统计。
- 完成课程、课时和学习记录。

### 阶段三：内容与社区业务

- 完成文件上传和作品发布审核。
- 完成作品详情、点赞、收藏和评论。
- 完成论坛、公告和内容管理。

### 阶段四：个人中心与数据可视化

- 完成个人主页和成长积分。
- 完成管理端数据概览和图表。
- 补充搜索、筛选、分页、空状态和异常状态。

### 阶段五：测试与交付

- 编写接口测试和核心业务测试。
- 完成前端联调、权限检查和文件上传测试。
- 完成部署、演示数据、项目说明和论文素材整理。

## 12. 测试计划

### 12.1 测试重点

- 注册登录、Token 失效和越权访问。
- 活动报名人数限制、重复报名和取消报名。
- 课程学习进度保存和重复提交。
- 作品上传、审核、下架及互动数据一致性。
- 分页查询、条件筛选和空数据展示。
- 管理员操作日志和异常提示。

### 12.2 验收标准

1. 三类角色只能访问其授权功能。
2. 核心业务流程可以完整闭环。
3. 关键数据在页面、接口和数据库之间保持一致。
4. 常见异常有可理解的提示，系统不因单次错误请求崩溃。
5. 项目可在说明文档提供的环境中完成启动和部署。

## 13. 部署方案

开发环境启动 MySQL、Redis、后端服务和前端开发服务器。生产环境由 Nginx 托管前端静态文件，并将 `/api` 请求转发到 Spring Boot 服务；数据库、Redis 和文件存储独立配置，敏感配置通过环境变量或配置文件管理。

建议准备：

- 数据库初始化脚本和演示数据脚本。
- 后端配置模板和启动说明。
- 前端构建、Nginx 配置和接口地址说明。
- 管理员测试账号及不同角色测试账号。

## 14. 迭代边界与扩展方向

### 14.1 首期必须完成

认证与权限、成员管理、活动管理、课程管理、作品发布审核、点赞评论、个人中心和基础数据统计。

### 14.2 二期可选功能

- AI 舞蹈点评：结合 MediaPipe 或 OpenPose，对姿态、节奏和动作完成度进行辅助分析。
- 舞者成长体系：积分、等级、勋章和排行榜。
- 内容推荐：根据舞种偏好、浏览和互动行为推荐课程及作品。
- 多社团支持：增加社团实体、社团管理员和社团数据隔离。
- 消息通知：站内信、活动提醒和审核结果通知。

扩展功能应在核心业务稳定后实施，避免影响首期系统交付。

# 阶段 3：课程与学习记录

## 1. 阶段目标

建立舞种课程内容管理能力，并支持用户按课时学习和保存进度。首期只实现课程目录、课时资料和完成状态，不实现复杂直播和付费能力。

## 2. 数据库设计

`course`：`id`、`title`、`cover_url`、`dance_type`、`difficulty`、`teacher_name`、`description`、`lesson_count`、`status`、`sort_no`、通用字段。

`course_lesson`：`id`、`course_id`、`title`、`video_url`、`duration`、`content`、`sort_no`、`status`、通用字段。

`learning_record`：`id`、`user_id`、`course_id`、`lesson_id`、`progress_seconds`、`completed`、`last_learn_time`、通用字段。用户、课时建立联合唯一约束。

## 3. 后端接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/courses` | 公开 | 分页查询已上架课程 |
| GET | `/api/courses/{id}` | 公开/登录 | 课程详情、课时目录和进度 |
| GET | `/api/courses/{id}/lessons/{lessonId}` | 登录 | 获取课时学习内容 |
| PUT | `/api/courses/{id}/lessons/{lessonId}/progress` | 登录 | 保存学习进度 |
| GET | `/api/courses/my` | 登录 | 我的学习课程 |
| POST | `/api/admin/courses` | 管理员 | 创建课程 |
| PUT | `/api/admin/courses/{id}` | 管理员 | 编辑课程 |
| DELETE | `/api/admin/courses/{id}` | 管理员 | 删除课程 |
| POST | `/api/admin/courses/{id}/lessons` | 管理员 | 新增课时 |
| PUT | `/api/admin/lessons/{id}` | 管理员 | 编辑课时 |
| DELETE | `/api/admin/lessons/{id}` | 管理员 | 删除课时 |
| PUT | `/api/admin/courses/{id}/status` | 管理员 | 上架或下架课程 |

课程详情返回 `completedCount`、`lessonCount`、`progressPercent`；进度更新采用幂等写入。完成课时时将 `completed` 置为 true，不能超过课时总时长。

## 4. 前端实现

- `/courses`：课程列表、舞种、难度和关键词筛选。
- `/courses/:id`：课程介绍、教师、课时目录、学习进度。
- `/courses/:id/lessons/:lessonId`：视频播放器、课时内容、完成按钮和自动保存进度。
- `/admin/courses`：课程 CRUD、上下架和课时管理。

播放器需要处理视频加载失败、播放进度保存失败、切换课时和未登录状态。管理表单支持课时排序，删除课时时提示影响范围。

## 5. 测试与验收

- 下架课程不会出现在用户端公开列表。
- 用户刷新或重新登录后学习进度保持不变。
- 重复保存进度不会产生重复记录。
- 课程删除前校验是否存在课时，删除策略在文档中保持一致。
- 课时顺序和管理端保存结果在用户端一致。
